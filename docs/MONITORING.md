# 見張りと数字

## 毎時のチェック（`.github/workflows/monitor.yml`）

1 時間に 1 回、アプリと同じ使い方で本番を確かめます（`tools/monitor/check.mjs`）。

| チェック | 失敗したときに多い原因 | 直し方 |
|---|---|---|
| サーバーの状態（`/api/health`） | Vercel のデプロイが壊れた / `GEMINI_API_KEY` が消えた | Vercel の `preplay` プロジェクトで、最新のデプロイと環境変数を確認する |
| AI で遊びを作る（`/api/generate`） | Gemini のクレジット切れ（HTTP 500、ログに 402）/ キーの失効 / モデルの提供終了 | AI Studio で残高とキーを確認する。モデルの提供終了なら Vercel の環境変数 `GEMINI_MODEL` を新しいモデルにする |
| みんなの遊び（Supabase） | 無料プランの一時停止（しばらく使われないと止まる）/ 障害 | Supabase のダッシュボードでプロジェクトを再開する |

- 失敗すると、ラベル `monitor` の Issue「本番で問題が起きています」が 1 件だけ作られます。GitHub が、このリポジトリを Watch している人にメールで知らせます
- 直ると、次のチェックで Issue に「復旧しました」と書いて自動で閉じます
- 一度失敗しても、30 秒後にもう一度試してから失敗とします（一瞬のネットワークの不調では知らせません）
- AI のチェックは Gemini を 1 時間に 1 回呼びます。`gemini-3.1-flash-lite` なら、1 か月でも数十円です
- このチェックは下の数字には入りません（`x-preplay-monitor` ヘッダーで区別しています）
- 手動で試すとき: Actions →「Monitor」→ Run workflow。手元では `node tools/monitor/check.mjs`

## 週間レポート（`.github/workflows/weekly-report.yml`）

毎週月曜の朝（日本時間 9 時すぎ）に、先週 7 日分の数字を Issue「週間レポート」にまとめます（ラベル `weekly-report`、前の週の Issue は閉じます）。

- **AI で遊びを作った回数**: 日ごとの成功・失敗・混雑で断った数（1 分に 10 回を超えた人）・不正な要求
- **AI の遊びの評価**: 👍 と 👎 の数。👍 が多かった遊びは「みんなの遊び」に載せる候補、👎 が多かった遊びは AI への指示を直す材料
- **みんなの遊び**: 新しい投稿、通報、非表示になった遊びの数
- ダウンロード数やクラッシュは App Store Connect の「App 分析」で見られます（Apple が集めている数字なので、アプリに解析ツールは入れていません）

集めているのは「日付と結果の種類ごとの回数」と、👍👎 を押した AI の遊びの中身だけです。誰が使ったかは記録しません。

## 気をつけること

- **60 日間リポジトリに変更がないと、GitHub は定期実行を止めます。** そのときは GitHub からメールが届くので、Actions の画面で「Enable workflow」を押します
- Issue の通知メールが来ないときは、リポジトリの「Watch」が「Participating and @mentions」以外（「All Activity」など）になっているか確認します
