# Preplay 2.1

## 変わったこと

| | 内容 |
|---|---|
| 止まったら知らせる | 1 時間ごとに本番（サーバー・AI・Supabase）をアプリと同じ使い方で確かめ、失敗したら Issue で知らせ、直ったら自動で閉じる。詳しくは [MONITORING.md](MONITORING.md) |
| 数字を見る | サーバーが AI の成功・失敗の回数を日ごとに数える（誰が使ったかは記録しない）。毎週月曜に、AI の回数・👍👎・投稿・通報を Issue「週間レポート」にまとめる |
| 人数と時間で選ぶ | 42 種類すべてに人数と目安の時間を付けた。「すべて」タブで「2人／3〜5人／6人以上」「5分以内／10分以内」で絞り込める。カードと一覧にも「2〜8人・約5分」と出る |
| AI の遊びに 👍👎 | AI が作った遊びの下に「この遊びはどうでしたか？」。評価は Supabase の `ai_feedback` に入り、週間レポートに 👍 が多い遊び（「みんなの遊び」に載せる候補）と 👎 が多い遊び（AI への指示を直す材料）が出る |
| 電波がなくても困らない | 公式の 42 種類はもともとアプリ内にあり、オフラインでも遊べる。加えて、「みんなの遊び」は前回読み込んだ一覧を端末に残して表示する。AI が使えないときは「インターネットにつながっていない」「使いすぎ（1 分待つ）」と理由を出す |

バージョンはまだ 2.0.1 のまま（下の「オーナーの作業」2 で 2.1.0 に上げる）。

## マージしたあとに自動で起きること

- `Supabase` ワークフローが、`daily_stats`（日ごとの回数）と `ai_feedback`（👍👎）を本番 DB に作る（PR では使い捨ての Postgres でテスト済み）
- `Monitor`（毎時）と `Weekly report`（毎週月曜）が動き始める

2.0.1 のアプリにもこの変更は影響しません（API の形は変えていない、テーブルを足しただけ）。

## オーナーの作業

1. **バックエンドの再デプロイ**（マージしたあと。Vercel の `preplay` は Git と連携していないので、自動ではデプロイされない）
   - `cd backend && vercel --prod`、または頼んでもらえれば私がやります
   - 数を数えるための環境変数 `SUPABASE_URL` と `SUPABASE_ANON_KEY`（`config/app_config.json` と同じ公開用の値）は、Vercel に設定済み（2026-10-26）。未設定でも AI 生成は今までどおり動き、数えないだけ
2. **2.0.1 が審査を通って公開されたあとで**、`pubspec.yaml` を `2.1.0+11`、`appstore/metadata.yaml` の `version.versionString` を `2.1.0` にし、`whatsNew` を下の文面にする PR を作る（両者の一致はテストで確かめている。審査中のバージョンがあるあいだは新しいバージョンを作れないので、この PR では上げていない）。スクリーンショットも撮り直す（「すべて」タブが変わった）。頼んでもらえれば私がやります
3. **App のプライバシーの申告**に、👍👎 の分を足す
   - 「使用状況データ」→「製品の操作」: 目的「アプリの機能」と「分析」、ユーザーにリンクしない、トラッキングに使わない
4. ビルドと提出は 2.0.1 と同じ（[RELEASE.md](RELEASE.md)）

## リリースノート（案）

```
・「すべて」で、人数と時間から遊びを選べるようになりました
・遊びごとに、何人で何分くらい遊べるかを表示しました
・AIが作った遊びを 👍 / 👎 で評価できるようになりました。評価の高い遊びは「みんなの遊び」に載ることがあります
・電波がないときも、「みんなの遊び」は前回読み込んだ内容を見られます
・AIが使えないときに、理由と次にできることを表示するようにしました
```
